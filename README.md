### 🔴 Project 1: AWS Provisioning via Jenkins, Ansible and Kubernetes CI/CD

<img src="https://img.shields.io/badge/Servers-3%20EC2-FF9900?style=flat-square&logo=amazonaws&logoColor=white" alt="Servers" />
<img src="https://img.shields.io/badge/Region-ap--south--1-232F3E?style=flat-square&logo=amazonaws&logoColor=white" alt="Region" />
<img src="https://img.shields.io/badge/Pipeline-3%20stages-D24939?style=flat-square&logo=jenkins&logoColor=white" alt="Pipeline" />
<img src="https://img.shields.io/badge/Trigger-GitHub%20Webhook-181717?style=flat-square&logo=github&logoColor=white" alt="Trigger" />
<img src="https://img.shields.io/badge/Deploy-Kubernetes%20Pod-326CE5?style=flat-square&logo=kubernetes&logoColor=white" alt="Deploy" />

📂 **Repository:** [`Devops-automation-jenkins-ansible`](https://github.com/PushpenderKumar7505/Devops-automation-jenkins-ansible)

| | |
|---|---|
| 🎯 **Problem** | Creating cloud resources and deploying workloads by hand is slow, error-prone and hard to repeat. |
| 💡 **Solution** | A GitHub push triggers Jenkins, which copies playbooks to an Ansible server. Ansible then provisions an EC2 instance (`ec2.yml`) or deploys a Kubernetes pod (`pod1.yml`). |
| 🧱 **Stack** | `Jenkins` `GitHub Webhooks` `Ansible (amazon.aws, k8s)` `AWS EC2` `Kubernetes (minikube)` `kubectl` `SSH/SCP` `Ubuntu` |

```mermaid
flowchart LR
    DEV(["👨‍💻 git push"]) --> GH["GitHub"]
    GH -->|"webhook"| JEN["⚙️ Jenkins<br/>3-stage pipeline"]
    JEN -->|"scp + ssh"| ANS["📜 Ansible server"]
    ANS -->|"ec2.yml"| EC2["☁️ EC2 +<br/>Security Group"]
    ANS -->|"pod1.yml"| K8S["☸️ Kubernetes pod<br/>2 containers"]

    classDef default fill:#0f172a,stroke:#22d3ee,color:#e2e8f0,stroke-width:1.5px
    classDef aws fill:#0f172a,stroke:#ff9900,color:#e2e8f0,stroke-width:1.5px
    classDef k8s fill:#0f172a,stroke:#326ce5,color:#e2e8f0,stroke-width:1.5px
    class EC2 aws
    class K8S k8s
```

<details>
<summary><b>🔁 Execution sequence</b></summary>

```mermaid
sequenceDiagram
    autonumber
    actor Dev as Developer
    participant GH as GitHub
    participant J as Jenkins
    participant A as Ansible server
    participant AWS as AWS EC2 API
    participant K as Kubernetes node

    Dev->>GH: git push to main
    GH->>J: Webhook (push event)
    J->>GH: Stage 1: check out repository
    J->>A: Stage 2: scp playbooks (sshagent)
    J->>A: Stage 3: ssh, run ansible-playbook
    alt Job runs ec2.yml
        A->>AWS: Create security group
        A->>AWS: Launch EC2 instance and wait
        AWS-->>A: Instance running
    else Job runs pod1.yml
        A->>K: SSH, apply Pod definition
        K-->>A: Pod created
    end
    A-->>J: PLAY RECAP and exit code
    Note over J: Build marked SUCCESS or FAILURE
```

</details>

| Component | Implementation |
|---|---|
| **Jenkins pipeline** | 3 stages: `Github connect` → `ansible-server` (scp via `sshagent`) → `ansible deploy` |
| **EC2 provisioning** | `amazon.aws.ec2_group` and `amazon.aws.ec2_instance` create a security group and instance |
| **Security** | IAM role attached to the Ansible server, so no AWS keys are stored on it |
| **Kubernetes** | `pod1.yml` applies a two-container Pod with the `k8s` module on minikube |

**✅ Verification**

```bash
$ ansible all -m ping            # on the Ansible server → "ping": "pong"
$ kubectl get pods               # on the Kubernetes node → croma-pod listed as Running
$ kubectl describe pod croma-pod # both containers Running, Ready: True
```

<details>
<summary><b>🔎 Limitations and next steps</b></summary>

- SSH is open to `0.0.0.0/0` on the created security group; restrict it to a trusted CIDR.
- `ec2.yml` targets `us-west-2` while servers run in `ap-south-1`; move region, AMI and key into variables.
- Commit a `Jenkinsfile` for this project, as done in project 2.
- The pod runs `sleep` placeholder containers; replace with a real app and a Deployment.

</details>

### 🟡 Project 2: Automated AWS EC2 Provisioning via Jenkins CI/CD

<img src="https://img.shields.io/badge/Jenkins%20Job-Aws--project-D24939?style=flat-square&logo=jenkins&logoColor=white" alt="Job" />
<img src="https://img.shields.io/badge/Builds-6%20(5%20successful)-22c55e?style=flat-square&logo=jenkins&logoColor=white" alt="Builds" />
<img src="https://img.shields.io/badge/Last%20build-~18s-0ea5e9?style=flat-square" alt="Last build" />
<img src="https://img.shields.io/badge/Jenkinsfile-in%20repo-181717?style=flat-square&logo=github&logoColor=white" alt="Jenkinsfile" />

📂 **Repository:** [`Jenkins-ansible-aws-ec2-provisioning`](https://github.com/PushpenderKumar7505/Jenkins-ansible-aws-ec2-provisioning)

A GitHub push triggers the Jenkins job `Aws-project`. Its `Jenkinsfile`, stored in the repository, copies `ec2.yml` to an Ansible server and runs it to create a security group and an EC2 instance, with no AWS console steps.

`Jenkins` `GitHub Webhooks` `Ansible (amazon.aws)` `AWS EC2` `IAM Role` `Groovy` `YAML`

```mermaid
flowchart LR
    subgraph BEFORE["❌ Before: manual"]
        direction TB
        M1["Sign in to console"] --> M2["Create security group"] --> M3["Pick AMI, type, key"] --> M4["Launch and verify by hand"]
    end
    subgraph AFTER["✅ After: pipeline"]
        direction TB
        A1["git push"] --> A2["Webhook triggers Jenkins"] --> A3["Playbook copied to Ansible"] --> A4["ec2.yml creates infrastructure"]
    end
    BEFORE ==> AFTER
```

<details>
<summary><b>🔎 Limitations of this lab setup</b></summary>

SSH is open to `0.0.0.0/0` on the created security group, the pipeline uses `StrictHostKeyChecking=no`, Jenkins runs on plain HTTP, and the playbook region (`us-west-2`) differs from the servers (`ap-south-1`). Hardening steps are documented in the repository.

</details>
